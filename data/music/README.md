# 音乐原始证据层（实际采集，不是美术规则）

本目录是新 skill 的音乐数据组件，不是整套 DMX/设备数据的替代品。歌曲身份、源数据去重仍遵循主登记表；不得仅按音频/MIDI相同就合并不同编曲。

## 已实际保留

- 299 个 MIDI 成员的原始字节，按165个不同 SHA-256 无损去重保存于 raw_midi/。成员级来源仍有299行，参考库与AI转写身份不混淆。
- events/：全部轨道事件、原始 tick、源字节位置、顺序、meta payload、控制器/音色/弯音、配对音符和起音/释放力度。保留时间签名、tempo变更；不把释键时间冒充踏板延音结束。
- note_cache_checks.jsonl：68份原有逐音符缓存均与对应原始 MIDI 独立解析的事件集合一致。midi-facts 中 notes 计数不能代替音符数组。
- legacy_facts/、legacy_analysis_qa/：原有音乐事实/模型文字/音频分析/QA原件；通过来源目录的SHA定位，不改写估计为事实。
- glimmers_end_record_music.json.gz：单独完整保留该 record 内的1590个音符等音乐层。其声称的原始MIDI哈希未出现在打包的299 MIDI中，不能假称已从MIDI重新验证。
- deterministic_note_facts.jsonl.gz：按165份不同MIDI字节内容计算的音符数、音高计数、轨道/通道范围、逐秒起音数量/起音力度与tempo/meter事件。时间仍是 MIDI 时间，不是已与音频或喷泉帧对齐的时间。

## 入口

song_music_catalog.jsonl 为全部517个源ID提供音乐层和文件引用，包含211条供应者暂保留记录。主登记表可在完整去重后改变这些数量，不能硬凑旧197/192/210。

load_music.py 的 load_song_music(source_song_id) 读取指定歌的音乐原始事件、转写事件和质量标记；不会联网、部署模型、推测缺失音符。调用前不需要旧F1–F5/MC规则。每个MIDI输入先校验SHA。

引用的原始音频、完整工程record等仍在经过整包SHA验证的源归档里；本目录没有复制整套音频或全部巨型JSON。必须与主包的源归档定位器/按需读取器一同交付，不能把本目录的摘要宣称为全部原始数据。

## 质量边界

- 211暂保留ID中，192有按ID命名音频、191有转写MIDI、192有音频分析、41有QA；仅40份QA含音乐起音/偏移指标。
- 192转写任务中缺少的MIDI是 水仙十字_幽灯所及之崖glimmersend；旧运行日志的该任务报音频打开/格式错误。上传的旧日志只含131成功+1失败，不足以证明最新188成功进度的运行构成。
- 全部299 MIDI均通过本解析器结构检查，但10个参考MIDI无配对音符；189个MIDI成员没有显式meter事件。这不等于音乐有无拍号，也不说明转写正确率。
- 205个暂保留ID能按路径/哈希证据连到参考MIDI。文件关联不是录音版本一致性证明。13个暂保留record本身声明music_match_ambiguous。
- 音频分析是既有librosa估计：3份beat_times达到800上限，和弦模板强制在大小三和弦中选一个，结构边界是候选，不是确认的乐段。
- 旧QA有通道笛卡尔积索引风险、缺首写前未知值屏蔽、在同一组音符上优化偏移再报告分数；不得当成独立对齐证据。所谓重音是力度/音高启发式，不是已证实的听觉重音。
- 实际tothemoon_blk0_0s record保存audio_offset_s=+1.2，水仙十字_blk0_0s保存+5.0，两者均声明音乐匹配歧义。保留这些值及旧QA最优偏移作为不同来源，不互相覆盖，也不将旧−3扫描结果称为该record保存事实。
- 音频内容身份、录音与参考MIDI版本一致性、音频/项目/DMX各时钟偏移和漂移未独立重算。高起音覆盖率不能证明音乐理解或因果关系。

music_gaps.jsonl 对全部211暂保留ID逐项列出缺件及未验证项；原始数据存在、结构解析通过、缓存一致、音乐准确性与跨模态对齐是不同层级。
